## Отличия контрольного прогона от [5] — перечень для приложения, без номера таблицы

Чем контрольный прогон отличается от протокола и кода [5]:

- сегментатор SAM 2.1 Hiera-L вместо SAM, `points_per_batch` = 16;
- слой окон 2×2 (`crop_n_layers` = 1); в демо-коде [5] окон нет — ближайший аналог у нас `crop_n_layers` = 0 (4.2);
- DINOv2 ViT-L/14 с регистрами; 41,61 [5] получены с ViT-S/14 без регистров, 43,33 — с ViT-L/14;
- вход энкодера нормируется по среднему и отклонению ImageNet; в демо-коде [5] — нет;
- эталон — сырой снимок ракурса с маской S по рамке, а не профиль 1024² с белым фоном и маской GrabCut;
- фон вырезки — заполнитель варианта φ (у C(0,1.0) — чёрный); в коде [5] фон вырезки и профиля белый;
- независимые решения по маскам вместо взаимно-однозначного сопоставления;
- AP — по всем детекциям с оценкой s*, без порога 0,4;
- все вырезки приводятся к 448; в [5] вырезки меньше 448 не увеличиваются;
- фильтров предложений по площади рамки и заполнению рамки маской нет (в коде [5] есть);
- истина — 3 078 рамок по VOC XML раздачи; каким файлом разметки оценивался [5], неизвестно;
- энкодер в половинной точности (DINOv2 — fp16, DINOv3 — bf16); точность счёта в [5] не названа;
- рамка детекции — описывающая рамка маски в разрешении входа S (с шагом 4 пикс.);
- бины площади — по размеченной рамке в пикселях исходного снимка; в [5] и [8] система координат не названа;
- контрольные прогоны — на 160 сценах, метрики 4.3–4.6 — на 120 тестовых;
- какое из отличий даёт разницу с 41,61, работа не разделяет.

## Что стоит за строкой OWLv2 — без номера таблицы

OWLv2: на снимок после NMS — в среднем 796,2, наибольшее 1006 (полная галерея); кандидатов до NMS — до 5 184 рамок; рамок, вырожденных после обрезки по кадру (остаются ложными детекциями), — 21407 и 21426 (полная галерея / один эталон); эталонов без эмбеддинга запроса — 0, меток без эталона в протоколе «один эталон» — 0; модель — google/owlv2-large-patch14-ensemble, float32, вход 1008.

**Как читать строку OWLv2**: разность с ним — разность с методом при штатном входе OWLv2; она смешивает текстовый надзор с архитектурой, обучением детектора и разрешением входа (OWLv2 — штатный вход 1008, сцена сжимается в 8,1 раза; метод — сегментация на 2048 и вырезки из полного кадра) и чистой ценой текста не является; смешение по разрешению — против OWLv2. Отличия протокола OWLv2 (из записи `owlv2_hr_insdet.json`):

- не штатный вызов image_guided_detection с его постобработкой, а прямой вызов тех же головок (логиты равны штатным — env.json, owlv2_direct_vs_stock): штатная постобработка перенормирует оценки внутри запроса;
- одна метка на рамку: оценка по метке — max sigmoid(logit) по эталонам метки, метка — argmax;
- штатный порог NMS 0,3 — по всем рамкам снимка после назначения метки, а не внутри одного запроса;
- эталон без эмбеддинга запроса пропускается; в протоколе one_per_class его метка остаётся без эталона;
- вход 1008 (вся сцена приводится к нему) против 2048 у сегментатора и вырезок из полного кадра у метода;
- эталон — квадратная вырезка по рамке промпта без маски; у меток PART_MASK_LABELS OWLv2 получает объект целиком;
- рамка детекции предсказывается моделью, а не описывает маску; на PCB OWLv2 перенимает рамку эталона;
- оценка — сигмоида логита, а не косинус: строки AR с порогом 0,4 не приводятся;
- NMS после сопоставления; модель обучена с текстом (таблица 1.2);
- рамки обрезаются по кадру (в штатном пути не обрезаются); рамки, вырожденные после обрезки (целиком в сером паддинге), остаются ложными детекциями — их число: n_detections_zero_area_after_clip;
- кандидатов на снимок у OWLv2 — до 5 184 рамок до NMS, у метода — маски M(I) (в среднем около 166 на сцену HR-InsDet); порога оценки нет ни у кого, maxDets = 1000 — число детекций на снимок: detections_per_image.

Независимые решения по маскам вместо взаимно-однозначного сопоставления [5] — условие сравнимости со всей группой (а).
